# Task research and content review

Use this review for a candidate in the interactive cycle. It does not start a
GSC cycle for standalone writing requests or change measurement holds. Reuse
verified research; gather only the evidence missing from the decision.

## Resolve the task

For an ambiguous query or a proposed new or localized page, inspect a small
sample of actual result pages using the host's permitted search/browsing tools
or supplied dated research. An automatic intent label or a result snippet alone
does not establish the user's task. Record:

- Query, intended country/language, observation date, and the search source or
  supplied sample. Mark unverified market settings and unavailable results unknown.
- Inspected result URLs and the task each answers, including conflicting intents.
  Describe the observed sample without claiming it represents the whole SERP.
- User task, input, expected result and where it happens: website, extension,
  application or downloadable resource. Compare these with verified product behavior.

For example, selecting pages to save in a new PDF differs from removing those
pages. A general label such as "informational" cannot distinguish the operations.
If only a related query can be researched, label that evidence indirect. Wait on
the dependent recommendation when the intended task remains uncertain.

Optional keyword metrics need provider, date, market, units and page/domain scope
where applicable. [Authority Score](https://www.semrush.com/kb/747-authority-score-backlink-scores)
and [keyword difficulty](https://www.semrush.com/kb/1158-what-is-kd) are vendor
metrics, not ranking guarantees. [Search volume](https://www.semrush.com/kb/683-what-is-search-volume-in-semrush)
estimates query frequency; related terms can overlap. A sum is not unique people,
available clicks or revenue. Missing estimates do not prove no demand. No paid
research service is required; retain unknowns and continue independent checks.

## Choose the page before writing

Group synonyms that describe the same task and result, then inspect existing
owned destinations using the skill's intent and overlap checks. Prefer a useful
existing page. A proposed separate page needs distinct value: different steps,
constraints, evidence or results. A device name or rewritten outline alone is
insufficient. Shared UI does not by itself justify merging existing useful guides.
Keep working URLs and user paths; a keyword in a new name does not justify migration.

## Return a small brief

For a supported content recommendation, include these fields in the site's
existing observation, interpretation, proposal and verification report:

| Field | Required content |
| --- | --- |
| Task and evidence | Task, input/result, execution surface; dated product sources and inspected result URLs when research was needed |
| Destination and placement | Current URL, repository identifier and file path, and exact section or insertion point; explain any proposed new page's distinct value |
| Change | Supported opening answer or correction, only the steps/headings needed to close the gap, and relevant limits |
| Proof and gaps | Observed result or useful example, its source, and unperformed checks; separate a demo from a completed operation |
| Measurement | Existing hold or, after implementation, fixed baseline and +14/+28-day checks; business outcomes need their own evidence |

Competitor pages can reveal questions; product evidence supports the answers.
Describe installation or external-app requirements honestly. Propose a result
check when it is missing, using an authorized non-sensitive sample. Reading copy
does not prove the operation worked, and this review does not authorize installs,
uploads or account actions. A successful desktop test does not establish mobile
support. Do not block a supported desktop-only brief on unrelated mobile testing.

[Google's helpful-content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)
supports original value, accurate claims and satisfying the user's task. The brief
above is an editorial workflow, not a ranking formula. Use real authorship and
product facts. [Google's SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
does not prescribe a word count, heading count or domain-keyword formula.
Editorial cleanup does not validate facts or establish ranking gains.
[Spam policies](https://developers.google.com/search/docs/essentials/spam-policies)
still apply to keyword stuffing, manipulative links and scaled low-value pages;
site age does not create an exemption. This review produces no link/profile
campaign, external publication or bulk page generation.

## If the candidate is localized

Check actual local task/market evidence and the translated content, steps and
limitations. Preserve working language URLs; a literal keyword translation is
not a demand study. Review language switching, variant discovery and intended
canonical/hreflang relationships for the candidate. [Google's multilingual guidance](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
describes several URL architectures; folders are one option. Propose one bounded
candidate, or wait on missing evidence, within the site's existing change and
measurement cycle. The technical checker does not validate translations or hreflang.
